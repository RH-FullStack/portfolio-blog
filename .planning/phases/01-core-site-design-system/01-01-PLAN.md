## Phase Goal (user story)

**As a** visitor (a potential employer, client, or reader), **I want to** browse Rasmus's fully designed, responsive, accessible core site — home, about, projects, and contact — in my preferred light or dark theme, **so that** I can quickly understand who he is, see his work, and know how to reach him.

> This plan (01-01) is the Walking Skeleton: it proves the entire stack end-to-end (build → route → self-hosted fonts → design tokens → typed data read → one real UI interaction) and ships the first live, themeable page (the homepage hero). Every later plan in this phase adds a vertical slice on top of the architecture this plan establishes. See `01-SKELETON.md`.

<objective>
Scaffold the Next.js 16 App Router project from nothing, encode the approved Japanese-minimalist design system as Tailwind v4 `@theme` tokens, wire FOUC-safe dark/light theming (next-themes), and render the homepage hero end-to-end — proving the full stack works.

This delivers: **DSGN-04** (distinctive ink/paper + vermillion identity, Geist fonts — D-01/D-02), **DSGN-02** (dark/light with system default + persisted manual toggle — D-12/D-13), **DSGN-03** (partial: reduced-motion handling, semantic HTML, 44px touch targets), **DSGN-01** (partial: responsive hero), and **CORE-01** (homepage hero with name + role + one-line positioning + portrait + primary CTA — D-04/D-05/D-06).

Purpose: A brand-new repo has no code; this plan is the architectural backbone every subsequent slice reuses without renegotiation.
Output: A buildable, themeable app with a live `/` hero page.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry → build machine | Third-party package code executes at install/build time |
| site → external targets | Any `target="_blank"` anchor exposes the opener window unless `rel` is set |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-SC | Tampering | `npm install` of next-themes, @radix-ui/react-dialog, lucide-react, geist | mitigate | All six packages cleared `OK` by slopcheck + registry/repo cross-check in 01-RESEARCH.md Package Legitimacy Audit; none has a `postinstall` script. No `[ASSUMED]`/`[SUS]` package → no blocking human checkpoint required. |
| T-01-01 | Tampering | `Button` primitive external-link rendering (reverse tabnabbing) | mitigate | Bake `rel="noopener noreferrer"` into the shared `Button` primitive whenever `target="_blank"` is used, so every external link in the site inherits the protection automatically. |
| T-01-02 | Information Disclosure | `metadataBase` / `NEXT_PUBLIC_SITE_URL` | accept | Public site URL is non-secret by definition; defaults to `http://localhost:3000` in dev. No secrets are introduced this phase. |
| T-01-03 | Spoofing/Injection | Homepage content rendering | accept | All content is developer-authored typed TS (no user input, no `dangerouslySetInnerHTML`, no MDX in Phase 1); TypeScript validates shape at compile time. |
</threat_model>
