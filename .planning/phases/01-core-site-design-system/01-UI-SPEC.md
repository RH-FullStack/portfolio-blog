# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-rolled `components/ui/*` (Button, Card, Tag/Badge, Container, Prose) styled with Tailwind utility classes |
| Icon library | `lucide-react` (default recommendation — tree-shakeable, geometric/minimal line icons, fits Japanese-minimalist aesthetic; needed for Sun/Moon theme toggle, Menu/X hamburger, Github/Linkedin/Mail footer icons) |
| Font | Geist Sans (UI/body) + Geist Mono (reserved for code, used from Phase 2 onward) — self-hosted via `next/font` per D-02. CJK fallback stack required: `var(--font-geist-sans), 'Hiragino Sans', 'Noto Sans JP', sans-serif` (per CLAUDE.md Stack Patterns — do not bundle a full JP font family) |
| Token implementation | Tailwind v4 CSS-first `@theme` block in `globals.css` — no `tailwind.config.js`. Dark mode via `class` strategy (`next-themes` with `attribute="class"`, `defaultTheme="system"`, `enableSystem`) so the manual toggle (D-12) and system-preference default (DSGN-02) both work off the same mechanism. |

**shadcn gate — resolved without asking:** `components.json` not found (fully greenfield repo). Upstream research (`.planning/research/ARCHITECTURE.md`, "Design system primitives" row) already answers this question: hand-rolled `components/ui/*` + Tailwind utilities, explicitly "no heavy UI kit needed." This is treated as a locked upstream decision, not re-asked. `Tool: none`; registry safety gate is not applicable.

**Discretionary addition (flag for confirmation):** For the mobile nav hamburger overlay (D-11), recommend `@radix-ui/react-dialog` — a single headless, unstyled primitive (not shadcn, not a full kit) purely for the focus-trap / Escape-to-close / focus-return behavior that DSGN-03 (keyboard navigation, accessibility) requires and that is easy to get wrong hand-rolled. Everything else stays hand-rolled Tailwind. If the user/planner prefers a fully from-scratch overlay, this is a one-line swap, not a structural decision.

## Layout & Motion

| Property | Value |
|----------|-------|
| Layout philosophy | Centered, single-column, generous whitespace ("ma") — one focal thing at a time (D-04). No asymmetric/editorial grid. |
| Page container | `max-w-6xl` (1152px) — hero, nav, footer, project card grid |
| Prose container | `max-w-2xl` (672px) — About page body copy, any long-form text — keeps line length readable |
| Breakpoints | Tailwind defaults: `sm` 640px, `md` 768px, `lg` 1024px, `xl` 1280px |
| Nav breakpoint | Hamburger menu below `md` (768px); full horizontal nav at `md` and above (D-11) |
| Motion level | Subtle micro-interactions only (D-03) — gentle hover states (e.g., underline/opacity/color shift on links, slight scale/shadow on cards), smooth transitions. Not motion-free, not expressive/flashy. |
| Theme transition | Cross-fade ~150–300ms on background/text/border colors when toggling light/dark (D-13) — never an instant/no-transition swap. Implement via a CSS `transition` on `background-color, color, border-color` scoped to themed elements (avoid transitioning `all`, which causes jank on unrelated properties). |
| Reduced motion | Respect `prefers-reduced-motion: reduce` — disable the theme cross-fade and hover transitions for users who opt out (DSGN-03 baseline accessibility). |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions:
- **44×44px minimum touch target** for all icon-only interactive elements — theme toggle button, hamburger menu trigger, footer social icons (Github/LinkedIn/mail) — per DSGN-03 accessibility baseline. This is a minimum hit-area, not itself a new spacing token; pad a smaller icon (e.g., 20px) up to the 44px target with `padding`.
- Homepage section breaks (hero → featured-projects teaser) should default to `2xl`/`3xl` (48–64px) or larger, never `xs`/`sm`, to honor D-04's generous whitespace philosophy.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.6 |
| Label | 14px | 400 (regular) | 1.4 |
| Heading | 28px | 600 (semibold) | 1.2 |
| Display | 44px | 600 (semibold) | 1.1 |

Weights declared (exactly 2): **400 regular**, **600 semibold** — matches Geist's available static weights, no third weight needed.

Usage notes:
- **Display (44/600/1.1):** Homepage hero name/headline only.
- **Heading (28/600/1.2):** Page titles (About, Projects, Contact), major section headings.
- **Body (16/400/1.6):** Paragraph copy, About-page prose. Line-height set slightly above the standard 1.5 recommendation (1.6) to reinforce the generous-whitespace "ma" philosophy (D-04) — deliberate deviation, not a default.
- **Label (14/400/1.4):** Nav links, tag/badge text, footer links, timestamps/captions, form-adjacent microcopy.

## Color

Dual-theme contract (DSGN-02 + D-12 require both light and dark, with a persisted manual toggle). Palette direction: "ink & paper + vermillion accent" (D-01) — near-black/off-white neutrals as the base, one sharp hanko-stamp-inspired vermillion accent used sparingly.

### Light mode

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FAF9F6` (warm paper white) | Page background |
| Secondary (30%) | `#EFEDE7` (soft warm gray) | Cards, nav bar, footer, borders/dividers |
| Text | `#1C1B18` (near-black ink) | Body/heading text |
| Accent (10%) | `#C1440E` (vermillion / hanko red) | See "Accent reserved for" below |
| Destructive | `#B91C1C` | Destructive actions only (none exist in Phase 1 — reserved for future phases) |

### Dark mode

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#16150F` (near-black, warm-tinted ink) | Page background |
| Secondary (30%) | `#211F19` (warm charcoal) | Cards, nav bar, footer, borders/dividers |
| Text | `#F5F2EA` (paper off-white) | Body/heading text |
| Accent (10%) | `#E2632E` (brightened vermillion) | See "Accent reserved for" below — brightened vs. light mode to preserve contrast against a near-black surface |
| Destructive | `#EF4444` | Destructive actions only (none exist in Phase 1 — reserved for future phases) |

**Accent reserved for (explicit list — never "all interactive elements"):**
- Link text on hover/active + link underline
- Primary CTA button background (homepage hero "View My Projects" button)
- Active/current nav-link indicator
- Focus rings (`:focus-visible` outline) on all interactive elements
- A single accent detail inside the header monogram/mark (D-09) — the mark itself stays ink/paper, one small accent stroke only

**Not accent:** body text, large background surfaces, decorative fills, tag/badge backgrounds (tags use the secondary/neutral surface, not the accent color, so the accent stays reserved for interaction/emphasis only).

Verify both palettes meet WCAG AA (4.5:1 body text, 3:1 large text/UI) once implemented — the values above are the starting design tokens, not yet contrast-audited against final rendered surfaces.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (homepage hero, D-06) | "View My Projects" → links to `/projects` (pairs with the featured-projects teaser section, D-07) |
| Secondary CTA (Contact page, CORE-03) | "Email Me" as the mailto link label, **plus the plain-text email address always visible alongside it** (not mailto-only) — per PITFALLS.md UX Pitfall: some OS/browser combos have no configured mail client, so a visible copyable address is the fallback path |
| Empty state | Not applicable in Phase 1 — the curated project showcase (PROJ-01) is static build-time data (3–5 hardcoded entries), never empty. No dynamic/user-generated lists exist yet. Revisit when Phase 2's blog list can genuinely be empty. |
| Error state (404, CORE-04) | Heading: **"Page Not Found"**. Body: **"The page you're looking for doesn't exist or has moved."** CTA: **"Back to Home"** → `/` |
| Destructive confirmation | Not applicable — Phase 1 has no destructive actions (mailto/social links only, no data mutation, no delete-capable UI) |
| Theme toggle (accessibility label, D-12) | `aria-label="Switch to dark theme"` when currently light; `aria-label="Switch to light theme"` when currently dark — label must reflect the *action*, not the current state |
| Mobile nav trigger (accessibility label, D-11) | `aria-label="Open menu"` (closed state) / `aria-label="Close menu"` (open state) |
