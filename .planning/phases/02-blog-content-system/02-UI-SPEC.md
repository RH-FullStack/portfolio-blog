## Spacing Scale

Declared values (must be multiples of 4) — unchanged from Phase 1, reused as-is:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing (tag chip padding, metadata row item gaps) |
| md | 16px | Default element spacing (paragraph rhythm inside `Prose`) |
| lg | 24px | Section padding, gap between list-row title and metadata row |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks (homepage teaser section spacing, matches existing `py-16`) |
| 3xl | 64px | Page-level spacing (`py-16 sm:py-24` container padding, matches Projects/About pattern) |

Exceptions:
- Blog index / related-posts / homepage-teaser rows use a 1px hairline divider (`border-t border-ink/10 dark:border-ink-dark/10`) between rows — a border-width value, not a spacing token, but declared here since D-01 explicitly calls for "thin divider between posts."
- Tag chips used as links (tag-archive navigation, D-02/D-03) and the heading-anchor icon (D-13) must maintain a 44×44px minimum touch target on tap-capable viewports, consistent with `Button`'s existing `iconOnly` variant (`min-h-11 min-w-11`) — achieved via padding/hit-area, not by inflating the visible chip/icon size.

## Typography

Reuses Phase 1's fixed 4-size scale (no new sizes introduced this phase, per DSGN-04/D-04 "ma" discipline):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`text-body`) | 400 regular | 1.6 |
| Label | 14px (`text-label`) | 400 regular | 1.4 |
| Heading | 28px (`text-heading`) | 600 semibold | 1.2 |
| Display | 44px (`text-display`) | 600 semibold | 1.1 |

Applied this phase:

| Element | Class | Rationale |
|---------|-------|-----------|
| `/blog` index page H1 ("Blog") | `text-heading font-semibold sm:text-display` | Matches the exact established page-H1 pattern from `/about`, `/contact` (28px mobile → 44px sm+) |
| `/blog/[slug]` post H1 (post title) | `text-heading font-semibold sm:text-display` | Same page-H1 pattern — post title is the page's singular focal heading |
| `/blog/tags/[tag]` archive H1 ("Posts tagged '{tag}'") | `text-heading font-semibold sm:text-display` | Same page-H1 pattern, keeps all top-level blog routes visually consistent |
| Blog-index row title (D-01 "large clickable title") | `text-heading font-semibold` (28px, no responsive bump) | Largest available size below Display; creates clear hierarchy over the 14px metadata row without introducing a 5th size |
| List-row metadata line (date · reading time · tags) | `text-label` (14px/400) | Secondary information, visually subordinate to the title per D-01 |
| Related-post / homepage-teaser row (compact: title + date, D-07/D-17) | Title: `text-body font-semibold` (16px/600 via Tailwind's existing 400/600 weight pair) · Date: `text-label` (14px) | Deliberately smaller than the full-index row title — these rows are secondary to the article/homepage they sit within, never competing with the primary content's hierarchy |
| Post body prose (MDX-rendered content) | `text-body` (16px/400/1.6) via existing `Prose` component | BLOG-02 — no new typography, `Prose` already built for this in Phase 1 |
| Code blocks (`rehype-pretty-code` output) | `--font-mono`, `text-label` (14px) size for code text | Slightly smaller than body text, standard convention for code blocks; monospace differentiates from prose without a new size token |
| Heading-anchor link glyph (D-13) | `text-label` (14px), `text-ink/40` default, `text-vermillion` on hover/focus | Subtle by default (doesn't compete with the heading), reveals accent color only on interaction |

## Color

Reuses Phase 1's fixed palette (no new colors introduced):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-paper` `#FAF9F6` / `--color-paper-dark` `#16150F` | Page background across all new blog routes |
| Secondary (30%) | `--color-secondary` `#EFEDE7` / `--color-secondary-dark` `#211F19` | Tag chip fill (`Tag` component, D-02), code block background surface |
| Accent (10%) | `--color-vermillion` `#C1440E` / `--color-vermillion-dark` `#E2632E` | Reserved for: post title hover/focus underline on index rows; tag chip text/border when it acts as a link to `/blog/tags/[tag]` (hover/focus state only — resting state stays neutral per D-02); heading-anchor link glyph on hover/focus (D-13); "View all posts" link (D-18) matching the existing "View all projects" treatment; inline MDX prose links (`<a>` tags inside post body); active/current-tag indicator on the `/blog/tags/[tag]` archive page |
| Destructive | `--color-destructive` `#B91C1C` / `--color-destructive-dark` `#EF4444` | Not used this phase — no destructive actions exist in blog browsing/reading (read-only content) |

Accent reserved for: post-row title hover/focus state, tag-chip-as-link hover/focus state, heading anchor-link glyph hover/focus, "View all posts" CTA link, inline prose links inside MDX body, active-tag indicator on tag archive pages. Never used for resting-state tag chips (D-02), metadata text, or related-post/teaser row text — those stay neutral ink/paper.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "View all posts" — links `/blog`, placed under the homepage latest-writing teaser (D-18), matching the existing "View all projects" pattern exactly |
| Empty state heading | "No posts yet" |
| Empty state body | "New writing is on the way — check back soon." (Defensive copy only: D-14's launch plan ships 2-3 real posts, so this state is not expected to be visitor-facing at launch, but `getAllPosts()` must handle a zero-post result gracefully without a broken/blank layout.) |
| Error state | Unknown `/blog/[slug]` or `/blog/tags/[tag]` routes resolve to the existing root `not-found.tsx` (Phase 1, CORE-04) via `dynamicParams = false` — no new 404 copy needed. Reuses: H1 "Page Not Found", body "The page you're looking for doesn't exist or has moved.", link "Back to Home". |
| Destructive confirmation | None — this phase has no destructive actions (blog browsing/reading is read-only for visitors; publishing is a git-push authoring workflow with no in-app delete/destroy UI, BLOG-06). |
